# Арктика-М — рабочее место метеоролога

Локальное веб-приложение **0.2.2**: поиск продукции GPTL, скачивание GeoTIFF, цветосинтез, анализ исходного пикселя, профиль атмосферы и маршрут. Один Python-процесс, SQLite и браузер. Интерфейс и обзорная подложка работают без внешних картографических сервисов.

## Запуск

Нужен Python 3.10+; рекомендуются 3.11/3.12. Первая установка загружает NumPy, Rasterio, pyproj и Pillow в локальную `.venv`.

**Windows:** `install.cmd`, затем `start.cmd`.

**Linux/macOS:**

```sh
sh install.sh
sh start.sh
```

Откройте полный адрес, напечатанный сервером. По умолчанию доступ разрешён только с этого компьютера. Node.js, Docker, GPU и отдельная база данных не нужны.

## Работа

**Уже есть TIFF:** «Открыть GeoTIFF» → папка со снимками → дата и сеанс → канал или композиция. Исходники не перемещаются и не изменяются.

**Нужны новые данные:** «Подключение» → Bearer → дата → поиск в каталоге → выбрать файлы → папка сохранения → очередь. Очередь сохраняется; после перезапуска загрузки находятся на паузе. Ручная замена Bearer сбрасывает реквизиты предыдущего входа.

**Анализ:** выберите область карты и продукт, щёлкните по карте. Инспектор показывает численные каналы, разности и тематические пояснения. Цветовые легенды относятся к выбранному рецепту. Профиль CSV/JSON подключается отдельно для температуры слоя, жидкого конденсата, интегралов и сопоставления яркостной температуры с высотой.

**Маршрут:** поставьте или введите узлы, задайте время отправления и скорость, выполните расчёт. Спутниковые значения и профильные условия имеют отдельное происхождение. После изменения маршрута, профиля или срока прежний результат скрывается.

## Что является результатом

| Функция | Содержание |
|---|---|
| Каналы | Исходные значения; температура только при объявленной шкале |
| RGB | Круглосуточная/ночная микрофизика, контраст пыли/пепла; фиксированные растяжки |
| Спектральные признаки | Межканальные разности и исследовательские кандидаты фазы, не классификатор облаков |
| Высота | Все пересечения `T(z)=Tя` и температурная чувствительность при подтверждённых предпосылках |
| Условия в слое | Температура и жидкая вода из внешнего профиля; без оценки интенсивности обледенения |
| Влагосодержание | Интегралы `q dp/g`, конденсата и переноса по заданным уровням профиля |
| Динамика | Корреляционное слежение вперёд/назад; кандидаты вращения рисунка, не ПМЦ |
| Экспорт | GeoTIFF, PNG, легенда, происхождение; маршрут CSV/GeoJSON; анализ точки JSON |

UInt16 и значения порядка 200–300 сами по себе не устанавливают единицы K. Опция **«Допущение DN=K»** предназначена для исследования и сохраняется в экспорте. Каналы 1–3 не переводятся в температуру. Спутниковая температура вершины не является температурой воздуха на эшелоне, а лёд на вершине не устанавливает обледенение самолёта.

## ERA5 и автоматический подбор шкалы — эксперимент

В окне «Температурная шкала» доступна кнопка «Автоматически подобрать шкалу по ERA5». Приложение запрашивает два окружающих часа и нужные профильные поля, сохраняет проверяемый кэш, отбирает открытые водные участки и рассчитывает опорную яркостную температуру через RTTOV 13.2 со спектральным аналогом МСУ-ГС «Электро-Л» №2. Принятие шкалы отдельно; только выбранный срок и проверенный диапазон DN. Универсальные коэффициенты DN→K для «Арктики» не назначаются.

Для получения ERA5 установите дополнительные зависимости в ту же среду Python:

```sh
.venv/bin/python -m pip install -r requirements-era5.txt
```

RTTOV с Python-обёрткой устанавливается отдельно по инструкции NWP SAF. Без него доступны проверка запроса и загрузка ERA5, но температурные опоры не выдумываются. `.cdsapirc`/PAT относятся к CDS, `.netrc` NCAR — к GDEX; файл доступа импортируется через интерфейс и остаётся в памяти до остановки сервера. Не переносите пароль NCAR в CDS.

[Настройка доступа, RTTOV и ограничения метода](docs/ERA5.html). Текущий расчёт требует явного задания постоянного зенитного угла небольшой опорной области. Независимой облачной маски, автоматического восстановления орбиты и холодных облачных опор в этой ветви нет. Успешная подгонка к модели не означает подтверждение калибровки поставщиком.

## Разработка и проверка

```sh
python check.py
python -m unittest discover -s tests -v
python -m compileall -q arktika server.py
python scripts/manifest.py --check
```

Для браузерных тестов, отдельно от зависимостей приложения:

```sh
python -m pip install 'playwright>=1.50,<2'
python -m playwright install chromium
python scripts/browser_smoke.py --output browser-results
```

Тестовые профили и небольшие тестовые TIFF создаются программно и обозначены как синтетические. Они проверяют код, не метеорологическую точность. Приёмка по настоящим наблюдениям описана отдельно в [VERIFICATION.md](docs/VERIFICATION.md). Секреты, пользовательские TIFF и локальные журналы в репозиторий не включаются.
