# Подключение адаптеров производных продуктов

Приложение обнаруживает дополнительные адаптеры через Python entry-point group `arktika.derived_product_adapters`. Пакет должен быть установлен в то же окружение Python, из которого запускается локальный сервер. После перезапуска адаптер появится в `/api/derived-adapters`.

Пример записи в `pyproject.toml` стороннего пакета:

```toml
[project.entry-points."arktika.derived_product_adapters"]
pmc_research_v1 = "my_pmc_adapter:adapter"
```

Entry point должен возвращать экземпляр адаптера или класс без аргументов. Объект предоставляет `spec: AdapterSpec` и метод `derive(inputs) -> двумерное численное поле`. `AdapterSpec.adapter_id` обязан совпадать с именем entry point. Контракт полей, сетки, CRS, точного UTC, единиц, источника, контрольной суммы и паспортной записи проверяется до сохранения. Сетевые реквизиты и пути не являются допустимой частью provenance.

API принимает только ID адаптера и ID ранее полученных локальных полей; он не загружает Python-код по пути из HTTP-запроса. Ошибка стороннего адаптера не останавливает приложение и возвращает в каталоге общий код `not_loaded`, без текста исключения, который мог бы раскрыть локальные пути или реквизиты. Третий-party адаптеры могут объявляться только как `experimental` или `planned`; статус `implemented` требует включения и проверки в самом приложении.

Наличие точки входа подтверждает подключение кода, но не научную корректность алгоритма. Например, алгоритм обнаружения ПМЦ должен сохранять кандидатный статус, описывать входные предпосылки и быть проверен на размеченной независимой выборке, прежде чем получать прикладной статус. Совмещение ERA5, CARRA2 и MERRA-2 либо спутниковым материалом само по себе не является метеорологической валидацией.
