Поля реанализа на общей карте

ERA5, CARRA2 и MERRA-2 работают независимо от спутникового снимка. Каждый слой хранит собственные источник, переменную, уровень, срок, маску отсутствующих данных и происхождение. Температурная шкала спутника и RTTOV для этого не нужны.

От источника к карте

1. Открыть «Источники данных» кнопкой с ключом. У нужного реанализа нажать «Добавить поле». Второй вход — «Слои» → «＋» у полей реанализа.

2. Настроить доступ. Из окна поля это можно сделать кнопкой «Настроить доступ» с возвратом к выбранному полю. ERA5 и CARRA2 используют общий токен CDS; MERRA-2 — отдельный Earthdata User Token либо .netrc. Реквизиты хранятся только в памяти процесса, не в браузерном хранилище и не в файле кэша.

3. Выбрать поле, уровень и точный срок UTC. Для температуры, влажности, высоты, ветра и ω на изобарической поверхности требуется уровень. Для температуры 2 м, ветра 10 м и давления на уровне моря он не задаётся.

4. Проверить область. Ввод: север, запад, юг, восток в градусах. Кнопка «Границы выбранной области карты» берёт границы регионального шаблона, не текущего увеличения. Запад больше востока означает пересечение 180°; сервер делает два подзапроса.

5. Нажать «Загрузить и добавить на карту». Подготовка выполняется в отдельном процессе. Окно можно закрыть; состояние доступно в панели слоёв. Отмена останавливает именно текущую задачу полей. Завершённые файлы не теряются. Отмена локального процесса не гарантирует снятие уже принятой задачи из очереди CDS.

6. Управлять наложением. Галочка включает слой, ползунок задаёт непрозрачность, стрелка перемещает выше в наложении, крестик убирает из карты, но не удаляет данные. Доступны заливка, изолинии и стрелки ветра. Всего до восьми слоёв.

7. Щёлкнуть на карте. Инспектор покажет значения видимых полей в ближайших исходных узлах, отдельно для каждого источника. Снимок не требуется. Существующий анализ спутникового пикселя остаётся отдельным результатом.

Поля и единицы

Поддержаны температура воздуха на уровнях и на 2 м (°C), удельная влажность (г/кг), относительная влажность (%), геопотенциальная высота (м), ветер (м/с), давление на уровне моря (гПа), SST (°C), концентрация морского льда (%) и ω (Па/с). Набор зависит от источника: например, ω не запрашивается у CARRA2 вместо геометрической вертикальной скорости, а относительная влажность MERRA-2 не вычисляется из неподготовленных величин.

При чтении K переводятся в °C, Па — в гПа, кг/кг — в г/кг, геопотенциал — в геопотенциальную высоту с g₀ = 9,80665 м/с². Единицы берутся из метаданных, не из диапазона чисел. Неизвестные единицы, неоднозначное время, ненулевой прогнозный шаг и невыбранные ансамблевые измерения останавливают обработку.

Ветер ERA5/MERRA-2 использует восточную и северную компоненты. Ветер CARRA2 получается из скорости и метеорологического направления; файл с объявленным направлением относительно сетки не должен трактоваться как географический. Стрелки показывают направление движения воздуха, а не направление, откуда он дует. Длина стрелки условна; скорость и направление «откуда» видны в инспекторе. При штиле направление не назначается.

Разности и совместный анализ

В окне добавления поля раскрыть «Разность двух источников: A − B». Выбрать два исходных поля с одинаковыми переменной, единицами, уровнем, типом времени и сроком. Например, A = MERRA-2, B = ERA5. Нажать «Рассчитать разность».

Результат вычисляется в узлах более грубой исходной сетки по ближайшим узлам второго источника, с пересечением масок. Это точечное сопоставление, не консервативное усреднение по ячейкам. Билинейная интерполяция и повышение детализации грубого реанализа не выполняются. Производный слой имеет симметричную относительно нуля шкалу. Разность скоростей ветра — скалярная разность модулей, не разность векторов.

Наложение не является ассимиляцией или ансамблевым прогнозом. Реанализы не усредняются автоматически. Несовпадение сроков со снимком или между слоями показано явно. Календарь снимков не переключает сроки уже добавленных полей. Нет автоматического обнаружения ПМЦ, расчёта вероятности ОЯ или вывода «безопасно» по отсутствующим данным.

Локальные файлы и автономная работа

Раскрыть «Импорт локального NetCDF / GRIB» и указать полный путь на компьютере, где работает Python-сервер. Исходный файл остаётся неизменным. Выбранные источник, переменная, уровень и время проверяются против структуры файла. Название источника локального файла — декларация пользователя; приложение не выдаёт её за независимо проверенное происхождение.

Для GRIB нужны дополнительные библиотеки:

python -m pip install -r requirements-grib.txt

Команда выполняется интерпретатором окружения приложения. Обычный установщик включает библиотеки NetCDF, CDS, OPeNDAP и отображения полей. Для автономной установки предусмотрен существующий параметр python install.py --wheelhouse /путь/к/колёсам.

Кэш находится в каталоге состояния: reanalysis/fields/<id>/field.nc и metadata.json. Ключ включает источник, поле, уровень, UTC, область и версию адаптера; для локального файла — также SHA-256. При повторном запросе проверяется контрольная сумма. Стек слоёв сохраняется в SQLite. После перезапуска готовые поля доступны без повторной авторизации.

«NetCDF + отчёт» экспортирует нормализованную исходную сетку и её численные значения, геолокацию CF, источник, запрос и контрольные суммы. Для температурной разности единицы в NetCDF — K; разность в K численно равна приращению в °C. Выходной PNG предназначен для визуализации и не заменяет значения исходных узлов.

Границы реализации

Карта сохраняет существующий SVG-движок и предопределённые области. Рендер обычно 1000 пикселей, до 2048 через API; увеличение изображения не повышает разрешение модели. Реализована ближайшая исходная ячейка, а не интерполяция по времени. Пространственные поля не подключаются автоматически к старому расчёту высоты облаков или маршрута. Нет многокадровой анимации и общих прогнозных сроков.

Один входной файл/ответ — до 1 ГиБ, поле — до 9 млн узлов; автоматический запрос блокируется при превышении кэшем 20 ГиБ. Самостоятельной очистки кэша нет. После аварийной остановки незавершённая задача помечается прерванной, а не успешной.

Проверка и первичные источники

Технические тесты используют явно синтетические файлы. Они проверяют программные контракты, арифметику, отображение и ошибки, но не точность реанализов. Для научной приёмки нужны реальные контрольные события и сравнение с независимыми наблюдениями. Сетевая приёмка с персональными CDS/Earthdata-реквизитами выполняется отдельно.
