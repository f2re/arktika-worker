Арктика-М — рабочее место метеоролога

Локальное веб-приложение 0.2.2: поиск продукции GPTL, скачивание GeoTIFF, цветосинтез, анализ исходного пикселя, профиль атмосферы и маршрут. Один Python-процесс, SQLite и браузер. Интерфейс и обзорная подложка работают без внешних картографических сервисов.

Запуск

Нужен Python 3.10+; рекомендуются 3.11/3.12. Первая установка загружает NumPy, Rasterio, pyproj и Pillow в локальную .venv.

Windows: install.cmd, затем start.cmd.

Linux/macOS:

sh install.sh
sh start.sh

Откройте полный адрес, напечатанный сервером. По умолчанию доступ разрешён только с этого компьютера. Node.js, Docker, GPU и отдельная база данных не нужны.

Работа

Уже есть TIFF: «Открыть GeoTIFF» → папка со снимками → дата и сеанс → канал или композиция. Исходники не перемещаются и не изменяются.

Нужны новые данные: «Подключение» → Bearer → дата → поиск в каталоге → выбрать файлы → папка сохранения → очередь. Очередь сохраняется; после перезапуска загрузки находятся на паузе. Ручная замена Bearer сбрасывает реквизиты предыдущего входа.

Анализ: выберите область карты и продукт, щёлкните по карте. Инспектор показывает численные каналы, разности и тематические пояснения. Цветовые легенды относятся к выбранному рецепту. Профиль CSV/JSON подключается отдельно для температуры слоя, жидкого конденсата, интегралов и сопоставления яркостной температуры с высотой.

Маршрут: поставьте или введите узлы, задайте время отправления и скорость, выполните расчёт. Спутниковые значения и профильные условия имеют отдельное происхождение. После изменения маршрута, профиля или срока прежний результат скрывается.

Что является результатом

Установка и развёртывание

Требования

Python 3.10+, модуль venv и браузер с поддержкой SVG, fetch, dialog. Рекомендуется 3.11 или 3.12. Четыре прямые зависимости: NumPy, Rasterio, pyproj, Pillow. GDAL/PROJ приходят с совместимыми бинарными колёсами, если они доступны для платформы. GPU не нужен. Практический начальный ориентир — 4 ядра, 8 ГБ памяти и свободное место для архива; это проектная рекомендация, не результат измерения минимальной конфигурации.

Установщик использует --only-binary=:all:: неожиданная компиляция GDAL не запускается. При отсутствии подходящего колеса установка останавливается, не изменяя системные библиотеки. На старых Astra/Linux необходимо отдельно проверить Python, glibc и наличие подходящих колёс. Совместимость с Astra 1.6/1.7 не заявляется.

Windows

Распаковать проект в обычную пользовательскую папку, например C:\Users\NAME\Apps\arktika-worker. В установщике Python включить команду py. Запустить install.cmd, дождаться успешной проверки. Затем start.cmd. Все вычисления выполняются Python на этом компьютере, папку сохранения можно выбрать на другом диске или доступном сетевом ресурсе.

install.cmd не устанавливает сам Python. При ошибке посмотреть текст над последней строкой, а не повторять запуск от администратора. Права администратора не требуются.

Linux и macOS

В подготовленной среде выполнить sh install.sh, затем sh start.sh. На системах, где venv вынесен в отдельный системный пакет, его устанавливает администратор стандартным способом. Скрипты не добавляют репозитории и не меняют системный Python.

На macOS Python должен доверять системным/корпоративным CA. Ошибка CERTIFICATE_VERIFY_FAILED устраняется установкой корректных сертификатов для Python. В коде нет режима отключения TLS.

Параметры

.venv/bin/python server.py --port 8765 --data-dir ./data --download-dir /srv/arktika/downloads
.venv/bin/python server.py --import /path/to/arktika_check
.venv/bin/python server.py --import-local /path/to/Arktika-M
.venv/bin/python server.py --no-browser --config config/app.json

--token-file принимает путь к файлу с одним Bearer: содержимое читается в память, путь не попадает в команду запроса к GPTL. Файл должен быть доступен только владельцу. Не помещать его в Git. Экспортированный GPTL_TOKEN тоже поддерживается; удобнее ввод в интерфейсе.

Копировать config/app.example.json в config/app.json нужно только для настройки OAuth, папки или начальной калибровки. config/app.json исключён из Git. Изменения калибровки в интерфейсе сохраняются в локальной базе и имеют приоритет при следующем запуске.

Сервер Linux без графического окружения

Сервер намеренно слушает только 127.0.0.1. Для личного удалённого рабочего места применяют SSH-туннель на тот же порт:

ssh -L 8765:127.0.0.1:8765 user@server

Открыть в локальном браузере полный адрес с ключом, напечатанный удалённым процессом. Файлы сохраняются на сервере. Этот режим не создаёт многопользовательскую систему: нет ролей, персональных очередей и аудита нескольких операторов. Публичный reverse proxy без переработки авторизации запрещён эксплуатационной моделью MVP.

Автозапуск Linux

В config/arktika-worker.service.example приведён шаблон systemd для отдельного непривилегированного пользователя. Изменить пути и имя пользователя перед установкой. Рабочий каталог данных должен быть доступен этому пользователю. Нельзя использовать один SQLite-каталог из двух процессов.

Офлайн-установка

На машине с той же ОС, архитектурой и версией Python подготовить колёса:

python -m pip download --only-binary=:all: -r requirements.txt -d wheelhouse

Перенести wheelhouse и проект, выполнить python install.py --wheelhouse wheelhouse. Колёса Linux не подходят для Windows. Не включать чужие системные библиотеки и шрифты в комплект. Сетевое получение новых снимков, естественно, требует связи с GPTL; локальные сцены, карта и обработка работают без сети.

Обновление и резервная копия

Остановить сервер; сохранить data/ и выбранную папку скачивания. Обновить только код, выполнить установщик и проверки. Не удалять .part ради обновления: очередь и журналы Range обеспечивают безопасное продолжение. Уже готовые исходники не перезаписываются. В версии 0.2 нет автоматического удаления архива и квот; оператор контролирует диск.

Подключение, Bearer, OAuth и S3

Простой режим

Нажать «Подключение», вставить access token. Допускается чистое значение, Bearer ... или Authorization: Bearer .... Значение очищается из поля после отправки. Оно хранится в памяти Python-процесса, не в SQLite, localStorage, исходниках или журнале команд.

Нажатие «Подключить» сохраняет токен в памяти; фактическая проверка происходит при запросе каталога/объекта. Декодирование exp в JWT используется только для индикации срока. Оно не является проверкой подписи или подтверждением полномочий.

Один access token нельзя продлевать сам по себе. При его истечении вставьте новый или настройте refresh для своего зарегистрированного клиента. Программа не собирает пароль учётной записи и не пытается получить скрытые ключи из браузера.

Зарегистрированный OAuth-клиент

Официальное руководство GPTL предусматривает ручную регистрацию client_id и разрешённых redirect_url. Спецификация GPTL, разделы «Авторизация внешнего web-сервиса», «authorization code», «Обновление метки доступа»; проверено 22.09.2026.

Потребуется точный redirect http://127.0.0.1:8765/oauth/callback либо тот же адрес с явно выбранным портом. Имя выданного клиента записать в config/app.json или форму OAuth. Чужой client_id из примеров документации не подходит автоматически.

Реализация отправляет code challenge S256 (PKCE), случайный одноразовый state с ограниченным сроком, обменивает code на серверной стороне. Используются фиксированные HTTPS endpoint auth.gptl.ru, а не адрес из пользовательского ввода. Поддержку PKCE и локального redirect нужно согласовать при регистрации: живая регистрация этого приложения здесь не выполнена.

Если клиент конфиденциальный, задать GPTL_CLIENT_SECRET в окружении процесса. Не включать секрет в app.json и не передавать в URL браузера. Scope по умолчанию openid s3policy offline_access; фактические разрешённые scope определяет поставщик.

Refresh token можно получить из обмена кодом либо ввести отдельно для того же client_id. Он остаётся в памяти. Перед запросом API/STS выполняется попытка обновления, если до exp осталось не более 120 секунд. При неуспехе выводится ошибка; нет бесконечного перебора паролей. Закрытие приложения уничтожает токены в памяти; вход при следующем запуске выполняется заново.

Разные виды доступа

Каталог, временные реквизиты S3 и чтение конкретного файла — три отдельные проверки. В режиме auto опубликованный объект сначала читается анонимно. Если требуется разрешение, используется STS и подпись S3. Результат 403 подписанного чтения не мешает обычному открытому GET, когда объект публичный. Адрес объекта и права не изменяются.

STS обновляется отдельно от Bearer. Ошибки AccessDenied, ExpiredToken, SignatureDoesNotMatch, NoSuchKey выводятся раздельно. Сессия STS не означает доступ ко всем бакетам. Подписанный HTTPS URL используется как есть, без добавления Bearer. После перенаправления авторизация не переносится на произвольный хост.

Безопасность локальной сессии

Ключ запуска после # — не Bearer GPTL. Он нужен только для связывания браузера с локальным сервером. Сервер проверяет Host, Origin, SameSite-cookie и специальный заголовок для POST. Браузерный журнал и URL не должны содержать access/refresh token.

Не публиковать data/, личные отчёты *_LOCAL, подписанные URL, token-файлы и ключ запуска. Прежде чем передавать диагностику, просмотреть её содержимое. Локальное приложение не предназначено для одновременной работы недоверенных пользователей одной ОС.

Работа в интерфейсе 0.2

Снимки

Кнопка с датой открывает календарь. Месяц и год выбираются независимо; стрелки переходят к соседнему месяцу. Кружок под днём отмечает локальные сеансы, точка — каталог, вопросительный знак — непроверенный день. «Найти снимки» запрашивает день; соседняя пиктограмма календаря — месяц после подтверждения.

«Открыть GeoTIFF» регистрирует имеющиеся файлы с подпапками, не перемещая их. Щелчок по локальному сроку сразу показывает продукт. «Каналы и файлы» у записи каталога открывает выбор продукции. Очередь доступна через пиктограмму загрузки слева; папка назначения выбирается там же.

Продукт и карта

Пиктограмма слоёв открывает задачи. «Облачность» — круглосуточная микрофизика, «Низкие облака» — ночная, «Температура» — канал 9, «Фаза» — совместные спектральные кандидаты. Все рецепты и настройки шкалы доступны ниже. Отдельные каналы переключаются кнопками с номерами.

В списке областей указаны географические названия, а не только EPSG. Колесо меняет масштаб, перетаскивание — центр. Кнопка рамки возвращает область целиком. Слой ночи включается луной; спутниковый слой — глазом. Значок информации открывает легенду. Смысл цветов не переносится с одного продукта на другой.

Анализ точки

Щёлкните по облачной структуре. Справа появляются Tя9, межканальные разности и тематические карточки. «На чём основано» показывает значения и использованные условия. Полный список каналов свёрнут ниже. В режиме неизвестных единиц DN физические показатели не выдаются.

Профиль добавляется кнопкой «Профиль» сверху. Можно импортировать CSV или JSON с единицами, источником, координатами и сроком. В анализе выберите профиль и высоту AMSL. Для высоты вершины отдельно подтвердите облачный непрозрачный пиксель; подтверждения сбрасываются при смене точки. График T(z), все решения высоты и условия в выбранном слое находятся ниже спектральных карточек. Подробности: ANALYSIS.md.

Маршрут

Откройте маршрут слева, нажмите «Нарисовать» и поставьте точки. Узел можно перетащить; координаты редактируются в списке. Enter на узле переводит фокус к его координатам. Завершите рисование, задайте отправление, скорость, шаг и при необходимости профиль/высоту. Нажмите «Проанализировать маршрут».

График показывает оконный сигнал по расстоянию, таблица — значения и профильные условия. Экспорт CSV/GeoJSON содержит время прохождения, возраст наблюдения, спектральную гипотезу, температуру и жидкую воду в слое, когда они определены. Щелчок по строке исследует спутниковую точку на время наблюдения; маршрутные профильные результаты сохраняются в таблице/экспорте.

Экспорт и повторный запуск

Верхняя кнопка загрузки сохраняет весь геопродукт: PNG, GeoTIFF, легенду и отчёт. «Сохранить анализ» в инспекторе сохраняет численные значения, интерпретацию, профиль и допущения конкретной точки. Раздел «Мои» содержит ранее построенные продукты. Последние область, продукт, канал и дата запоминаются. Токены по-прежнему находятся только в памяти процесса.

Перед обновлением закройте старый сервер. Распакуйте новую поставку в отдельную папку; существующие TIFF можно импортировать повторно без копирования. Для продолжения той же базы используйте --data-dir с её прежним расположением после резервного копирования. Одновременно работать с одной базой двумя версиями не следует.

Анализ облачности, высоты и условий в слое

Версия 0.2.2. Модуль interpretation.py; сохранённый анализ содержит версию метода, значения всех использованных каналов, SHA-256 исходников, профиль, его радиус/срок и принятые оператором допущения.

Что стало рабочим инструментом

Щелчок по карте даёт яркостную температуру и четыре межканальные разности. Ни цвет PNG, ни обозначение RGB не участвуют в численной классификации. В карточке сначала показана интерпретация, затем применимость и следующий диагностический шаг. Конкретные числа и пороги раскрываются в «На чём основано».

При DN без температурной шкалы интерпретация температуры и фазы не выполняется. При осознанном DN=K используется та же арифметика, но статус допущения остаётся в карте, анализе и экспорте. Неуказанные коэффициенты одного канала не заимствуются у другого.

Цвета: только внутри выбранной композиции

У круглосуточной микрофизики R=T10−T9, G=T9−T7, B=T9. В описании EUMeTrain для SEVIRI плотные холодные ледяные вершины часто красные; тонкая перистая облачность может быть тёмно-синей; тёплая поверхность также увеличивает синий вклад. Поэтому подписи «синий всегда означает лёд» в приложении нет. Жёлто-зелёные/оливковые цвета совместимы с водяной и смешанной облачностью. Оттенок зависит от температуры, прозрачности и подстилающей поверхности.

Это справочная интерпретация опубликованной композиции, перенесённой на близкие каналы МСУ-ГС/А; не измеренная точность для Арктики-М. Для конкретного пикселя используются исходные каналы и приведённые ниже отдельно обозначенные инженерные правила. Источник: EUMeTrain, 24-hour Microphysics Quick Guide.

Профиль: импорт реальных наблюдений или модели

Необязательные массивы: pressure+pressure_units, specific_humidity+humidity_units: "kg/kg", cloud_liquid/cloud_ice+condensate_units: "kg/kg", u/v+wind_units: "m/s". vertical_reference только AMSL. Заготовка без вымышленных наблюдений — examples/profile_schema.json.

Высота облачной вершины

В анализе точки выберите профиль. Только для этой точки подтвердите облачность и непрозрачность. Затем решается T(z)=Tя9 на кусочно-линейном профиле. Возвращаются все пересечения, включая варианты при инверсии и плоские интервалы. При признаке тонкого облака T10−T9<−2 K простое сопоставление блокируется. При смене точки подтверждения сбрасываются.

Диапазоны высот при Tя±ΔT (по умолчанию 2 K) — чувствительность метода к выбранной температурной поправке, не измеренная ошибка и не статистический доверительный интервал. Отсутствие пересечения не заменяется высотой вне профиля. Высота в м/км над средним уровнем моря, не эшелон давления и не высота над рельефом.

Основные допущения: Tя9≈температура непрозрачной вершины, профиль репрезентативен; атмосферная коррекция и оценка эмиссии не выполнены. Полноценный алгоритм ВГО потребует облачной маски, радиационной модели и независимой верификации; пример архитектуры восстановления профилей NOAA.

Условия обледенения на выбранной высоте

Температура берётся интерполяцией T(z). Жидкая вода берётся из массива cloud_liquid этого профиля, а не переносится со спутниковой вершины. При −40<T<0 °C и ql>10⁻⁶ кг/кг выводится сочетание «переохлаждённая жидкая вода». Порог ql — инженерный порог разрешения численного поля. В приложении нет калиброванной категории интенсивности обледенения.

При наличии давления вычисляется ρ=p/[Rd·T·(1+0,608q)] и LWC=1000·ρ·ql в г/м³; без q используется отмеченное приближение сухого воздуха. При отсутствии давления выводится только ql в кг/кг. Нулевой/малый конденсат, тёплый воздух и отсутствие профиля не дают зелёного «безопасно». Тёплый воздух сам по себе не исключает обледенение холодной поверхности самолёта. Крупные капли, замерзающие осадки, мокрый снег, ледяные кристаллы и конструктивные особенности ВС не моделируются.

Физическая связь с переохлаждённой водой и зависимость опасности от температуры, размеров/концентрации частиц изложены в NWS Icing Hazards. Численные пороги нашего фильтра и интерполяция не заявлены как алгоритм NWS.

Влагосодержание и маршрут

W=(1/g)∫q dp; IVT=|(1/g)∫q(u,v)dp|. Давление в Па, q в кг/кг. W в кг/м² численно равен мм жидкой воды. Интегралы относятся только к заданному интервалу давления. При наличии ql/qi отдельно вычисляются столбовые количества жидкости/льда; это не синоним водяного пара.

На маршруте спектральная часть относится к снимку. Профиль слоя проверяется по месту и ожидаемому времени прохождения каждой точки. Экспорт сохраняет различие времени наблюдения и ETA. Щелчок по строке открывает спутниковую точку на время наблюдения, а не подменяет её маршрутным прогнозом. Пространственной модели, покрывающей весь маршрут, этот точечный профиль не заменяет.

Что проверять дальше

Нужны независимые облачная маска/фаза, профили и измерения жидкой воды; разделение выборки по событиям, сезонам, поверхности, углу визирования и аппарату. Сравнить исходные правила с базовым алгоритмом без спутника. Тесты арифметики и снимок интерфейса не являются оценкой точности классификации.

Обычный сценарий

Методики, ограничения и критерии научной готовности

1. Уровни результата

Наблюдение: хранимое значение DN либо документированная яркостная температура. Производный признак: спектральная разность, RGB, движение рисунка. Восстановленный параметр: величина из обратной физической задачи с моделью и неопределённостью. Прогноз: оценка будущего события, проверенная на независимой выборке. Программная реализация первого или второго уровня не доказывает наличие третьего или четвёртого.

L2IR — наименование уровня поставщика, а не доказательство K. UInt16, диапазон 190–300 и значения GDAL scale=1/offset=0 по умолчанию не являются калибровкой. Необходимо отдельное описание единиц и преобразования. Для линейного кодирования Tя[K] реализовано T = scale * DN + offset. Для спектральной яркости такого адаптера недостаточно: требуются единицы радиации, коэффициенты Планка/спектральная характеристика прибора. Автоматического угадывания в коде нет.

2. Каналы и соответствие рецептам

Реестр products.py: 1 — 0,575; 2 — 0,725; 3 — 0,85; 4 — 3,75; 5 — 6,35; 6 — 8,0; 7 — 8,7; 8 — 9,7; 9 — 10,7; 10 — 11,85 мкм. Это центральные длины волн, не полные функции спектральной чувствительности. Числа сопоставлены с метаданными предоставленной продукции и описаниями приборов; для калибровочного алгоритма требуются характеристики конкретного прибора/аппарата [S1, S2].

Нельзя объявлять канал 6 заменой водяного канала 7,3 мкм. Поэтому стандартный Air Mass RGB не включён. Нет канала 1,6 мкм для прямого переноса ряда снежных и дневных микрофизических рецептов.

3. Геометрия и арифметика

Перед совместной обработкой проверить срок, аппарат, прибор, сетку и единицы. Все каналы перепроецируются на одну целевую сетку. В MVP используется ближайший сосед, чтобы не создавать дробные значения из неподтверждённых DN и не смешивать классы. Это не восстанавливает утраченного пространственного разрешения. Для количественного продукта будущих версий выбор ресэмплинга должен проходить отдельную проверку [S3].

Вычитание выполняется в float32, а не UInt16. Общая маска — пересечение валидных пикселей требуемых каналов. Диапазон 120–400 K и |T10−T9|>15 K используются как диагностические сигналы несогласованности, не как доказательство метеоявления. У предоставленного образца встречался сильный выброс канала 10; флаг нельзя игнорировать ради более красивого RGB.

Минимум/максимум в легенде вычисляются на конечной сетке выбранной области, а не во всём исходном файле. Цветовая шкала отдельна от экстремумов; насыщение цветов не меняет численные значения. При отсутствии физической шкалы DN-отображение использует процентили 2/98 и не годится для автоматического сравнения разных кадров без фиксированных пределов.

5. Интегральная карта признаков

Классы имеют фиксированную легенду. 0 — нет данных; 1 — T9<233,15 K; 2 — ночью 2<T9−T4<10 K и T9>243 K; 3 — флаг контроля качества; 4 — признак не выделен. Приоритет: качество, ночной признак, холодный сигнал, прочее.

Не называть класс 1 автоматически кучево-дождевым облаком: холодная поверхность и другие типы облаков тоже дают холодный сигнал. Класс 2 не различает туман у земли и приподнятый водяной слой. Класс 4 не равен безопасности. Карта не является cloud mask, формой облачности или официальным предупреждением.

6. Маршруты

Расстояния и промежуточные точки рассчитаны по геодезическим WGS84. Выборка производится в исходных растрах, с сохранением пропусков и единиц каждого канала. ETA = отправление + накопленное расстояние / скорость. Возраст наблюдения = ETA − срок сцены. При отрицательном возрасте снимок позднее прохождения; при большом положительном — устарел к прохождению.

Нельзя использовать снимок одного срока как будущую погоду на протяжённом маршруте. Нужны последовательности, оценка неопределённости переноса и прогноз модели, а для авиации — ещё профиль условий на высоте. Нет данных о высоте и видимости — нет вывода о безопасности.

7. Движение и вращение

В motion.py реализованы нормированная корреляция окон 16×16, поиск смещения до ±5 пикселей на сетке 512 пикселей по ширине, шаг окон 24. Исключаются однотонные/невалидные окна, слабый максимум корреляции и максимум на границе окна поиска. Эти настройки — исходные инженерные параметры, не оптимизированные по метеорологической выборке.

В локальном поле смещений выполняется линейное приближение скорости от координат. Выделяются области, где оценённое циклональное вращение превышает деформацию и качество приближения достаточно. Это угловое вращение рисунка, не атмосферная вихревость на уровне 850 гПа. В MVP нет полноценной облачной маски, оценки высоты, компенсации межканальной/межспутниковой ошибки и устойчивого многокадрового сопровождения события; добавлена обратная проверка до 1 пикселя.

У ПМЦ важны не только спиральные облака: холодное вторжение, неустойчивость над морем, бароклинность, влажность и верхнее возмущение. Порог SST−T500 или потенциальной устойчивости зависит от конкретной методики и не переносится как универсальная вероятность. Исследования Stoll служат основанием для отдельного многопризнакового этапа [S7]. Т5 не является T500, Т9 под облаком не является SST.

8. Профильная лаборатория

Для водяного пара W = 1/g * ∫q dp, для переноса Q = 1/g * ∫q(u,v) dp, IVT=|Q|. Давление — Pa, q — kg/kg, ветер — m/s; результат W — kg/m² (равен mm жидкой воды), IVT — kg/(m·s). Водность облаков отдельно: интегралы ql/qi по давлению. Нужны реальные профили из наблюдений/модели с происхождением. Канал 5 и цветовая композиция их не заменяют.

Формат JSON для /api/profile:

{
  "pressure_units": "Pa", "humidity_units": "kg/kg", "wind_units": "m/s",
  "source": "Источник и идентификатор профиля", "valid_time": "2026-09-21T02:00:00Z",
  "pressure": [], "specific_humidity": [], "u": [], "v": []
}

Пустые массивы намеренно не образуют готового наблюдения; заполнить данными своей задачи. cloud_liquid и cloud_ice — необязательные массивы kg/kg тех же уровней. Уровни должны быть строго монотонны. Интеграл относится только к заданному интервалу давления: ограниченный профиль нельзя выдавать за весь столб.

Для упрощённого сопоставления с высотой:

{
  "mode": "cloud_top", "cloud_confirmed": true,
  "temperature_units": "K", "height_units": "m",
  "height": [], "temperature": [], "brightness_temperature": null
}

Возвращаются все пересечения T(z)=Tя и плоские интервалы. При инверсии ответ может быть неоднозначен. Метод не учитывает прозрачность, эмиссию и атмосферную поправку. Подтверждённая облачная маска задаётся независимо, а не выводится из температурного порога.

9. Проверка перед оперативным применением

Радиометрия: коэффициенты каждого аппарата/канала, распределение ошибок, дрейф, квантизация. Геометрия: совместимость каналов, повторных сроков и двух аппаратов, параллакс. Облачная продукция: независимые радиозондовые/наземные/лидарные/спутниковые сопоставления в подходящих масштабах.

ПМЦ: размеченные жизненные циклы и отрицательные примеры холодных вторжений без ПМЦ; разделение по событиям, сезонам и регионам. Не перемешивать соседние кадры между обучением и испытанием. Не использовать экстремум за будущую жизнь вихря как признак раннего прогноза. Сравнить «только модель», «только спутник», «совместно». Вероятность выводить только после проверки надёжности.

Маршруты: проверять положение и сроки пересечения опасных областей, политику устаревания и корректность неизвестных значений. Технические unit-тесты и красивые примеры не заменяют эту программу.

Модель данных и происхождение

Catalog item / asset

Catalog item: идентификатор ETRIS/STAC, аппарат, срок, исходная строка времени, time_assumed, уровень, прибор, геометрия/границы и источник. Asset: отдельный URI, имя, media type, уровень, канал, EPSG, размер, роли, регион S3. Роль visual не является достаточным признаком RGB-картинки: у L2IR поканальные GeoTIFF тоже могут иметь эту роль.

Срок нормализуется в UTC. Наивное время поставщика трактуется как UTC только с сохранением флага time_assumed; исходная строка не теряется в каталоге. Пределы поискового периода и его полнота хранятся отдельно от самих записей.

Идентификатор asset зависит от item ID и канонического адреса без временной подписи query. Обновлённый подписанный URL того же объекта не создаёт дубликат, но локальные URI остаются приватными и не попадают в обычный DTO интерфейса.

Локальная сцена

Сцена объединяет физические одноканальные TIFF по аппарату и сроку из имени. Каждый канал сохраняет реальный путь, CRS, размер и форму сетки. Путь — внутренняя информация базы. API сцен возвращает только безопасные описания. При двух копиях предпочтение отдаётся уже зарегистрированной EPSG:4326; разные варианты не смешиваются молча поверх одной копии. Полноценное управление несколькими версиями одного asset запланировано отдельно.

Имена других миссий/продуктов не угадываются. При обработке повторно проверяются CRS, одноканальность, наличие нужных каналов и шкала.

Processing run / product

Идентификатор продукта — SHA-256 (укороченный для каталога), вычисленный из хешей входов, запроса, целевой геометрии, калибровки, рецепта и версии алгоритма. Полные SHA-256 входных файлов сохраняются. Перепроверка размера/mtime во время чтения обнаруживает замену исходника. Не следует изменять зарегистрированные исходники внешним процессом.

product.json: ID, scene ID, аппарат и UTC, продукт, статус калибровки, сетка/CRS/transform, параметры, входные имена/размеры/хеши, легенда и список файлов. Секреты и исходные абсолютные пути не включаются.

display.tif: 4 канала RGBA uint8 с CRS; значения цвета после растяжки. values.tif: скаляр float32 с единицами, если у продукта существует скалярное поле. Для RGB такого поля нет. quality.tif: uint8, битовые флаги. map.png: отображение с прозрачностью. night.png: отдельный слой геометрической ночи. legend.json: единицы, пределы цвета, фактические статистики, формулы, ограничения. report.html: автономный обзор с берегами и легендой.

Публикация результата происходит после полной записи во временную .building папку и атомарного переименования. Неоконченные результаты не перечисляются как готовые. Уже рассчитанный идентичный продукт переиспользуется. Миграции версий алгоритма обязаны менять ключ кэша.

Маршрут

Вход: LineString/точки [lon,lat], скорость, время начала, шаг. Внутренние расчёты расстояния — WGS84 geodesic. В результате на каждой точке сохраняются координаты, накопленное расстояние, ETA, наблюдаемый срок, возраст, каналы с единицами, пропуски и текстовое ограничение. Значение null не заменяется нулём.

GeoJSON содержит точки выборки и общие сведения о единицах, сроке и источнике. Полный JSON дополнительно содержит параметры продукта и входные SHA-256. CSV — плоская таблица с единицами в названиях столбцов. Отсутствует ложное поле вероятности/безопасности.

Расширение модели

План: instrument_instance, calibration_version, navigation_quality, per_pixel_time, acquisition_footprint, valid_footprint, cloud_mask_version, uncertainty_field, model_cycle, forecast_valid_time, event_track, verification_run, route_corridor. Эти поля нельзя заменять длинной неструктурированной строкой примечаний. Наблюдение, восстановление и прогноз должны быть разными типами слоя.

Сущности 0.2

profiles/<hash>.json: нормализованный профиль с источником, местом, временем, единицами и пределами применения. Секретов подключения в этой схеме нет.

analyses/<hash>.json: исходные значения всех каналов, производные, карточки интерпретации, версия правил, SHA-256 всех использованных файлов, профиль и операторские подтверждения. Не заменяет файлы продукта.

Классы карты фазы документированы в ANALYSIS.md. Их численный растр и quality.tif сохраняются независимо от цветного GeoTIFF. Цвет PNG не используется как измерение. В маршрутных файлах добавлены phase/phase_label/metrics/profile_result, а в CSV — разности и профильные поля.

Архитектура MVP и границы масштабирования

Текущая схема

Браузер: календарь / карта / легенда / точка / маршрут
             │ localhost, cookie, JSON
Python HTTP API — Workstation — реестр продуктов
     │           │             │
     │           │             ├─ Rasterio / PROJ / NumPy / Pillow
     │           │             ├─ временная папка → атомарный продукт
     │           │             └─ маршрут на исходных пикселях
     │           └─ SQLite: каталог / сцены / полнота / настройки
     └─ клиент GPTL → STAC / OAuth / STS → S3
                         └─ очередь Range/ETag → архив GeoTIFF

Модульный монолит выбран сознательно: один процесс, одна база, нет обязательных Redis/Celery/PostGIS/Node-сервисов. Набор внешних зависимостей ограничен георастровым стеком. Подложка и код интерфейса локальные, внешний tile provider не нужен.

Сетевой слой отделён от научного: GDAL читает локальные файлы, не произвольные URL. Метаданные каталога нормализуются до обработки. Выдача STS не трактуется как разрешение прочитать все объекты. Загрузчик использует один механизм авторизации для пробного чтения и фактической передачи данных.

Один фоновый слот для поиска, импорта и обработки; один сохраняемый загрузчик. HTTP обслуживает небольшое ограниченное число запросов. SQLite WAL и lock защищают внутренние записи. Нативная обработка использует один поток GDAL для предсказуемого потребления памяти. Тяжёлое параллельное производство — не задача текущего HTTP ThreadingServer.

Контракты модулей

network отвечает только за транспорт и пагинацию. model — за понятия/идентификаторы/время. store — за индекс и состояния. processing — за чистую физическую арифметику после калибровочного барьера и экспорт. geo — за единый transform карты, Солнце и геодезию. routes не получает право объявлять прогноз. motion не получает право объявлять ПМЦ. profiles требует внешние профили.

products.registry() является источником состава интерфейса, описаний, единиц и статусов. Производственный алгоритм должен возвращать продукт с легендой и происхождением, а не только PNG.

Что масштабируется без замены архитектуры

Добавление рецептов, версий калибровки, областей, валидаторов, адаптеров наблюдений, асинхронного COG-тайлинга и фонового индексатора. Локальная эксплуатация может оставаться монолитной. Перед оптимизацией измерять чтение каталога, дисковый ввод, память warp и стоимость отрисовки; не строить распределённую очередь по предположениям.

Когда нужны отдельные сервисы

Несколько одновременных операторов, централизованный архив, одновременные задания на разные регионы, защищённая публикация, постоянное поступление снимков. Тогда HTTP переносится на поддерживаемый production ASGI/WSGI-сервер, вводятся пользователи/роли/CSRF/TLS/audit, хранение объектов отделяется от каталога, SQLite заменяется при необходимости на PostgreSQL/PostGIS, вычисления уходят в ограниченную очередь процессов.

Ни один из этих компонентов не обязателен для локального MVP. S3-совместимое хранилище может располагаться на существующем NAS; включение его в будущем не означает зависимость от внешнего облака.

Отказы и восстановление

HTTP 500 каталога: статус ошибки, данные других платформ не объявляются отсутствующими. Разрыв сети: сохранение корректной части и проверка версии объекта при продолжении. Изменившийся исходник: новый продукт, не подмена происхождения старого. Отмена обработки: .building не показывается как готовая продукция. Недостаток места: загрузка останавливается до переполнения; для производства больших растрoв требуются дополнительные квоты.

Токены исчезают при перезапуске процесса. Очередь сохраняется и переводится в паузу. Автоматическое удаление архива не реализовано; резервное копирование и дисковые квоты задаются эксплуатацией.

Границы применения 0.2.2

Научные

Калибровка предоставленных L2IR не подтверждена поставщиком. DN=K включается явно. Шкала TIFF, шаг сетки и уровень L2IR сами по себе не устанавливают точность радиометрии или геопривязки.

Спектральная карта не является облачной маской, классификацией формы, картой водности, НГО, видимости или ОЯ. На цвет влияют поверхность, прозрачность, влажность и геометрия. Пороговые фазовые кандидаты не имеют проверенной вероятности.

Высота по T(z) — сопоставление с внешним профилем без полноценной обратной задачи переноса излучения. Температурная чувствительность не является доверительным интервалом. Проверка радиуса/срока профиля не гарантирует его репрезентативности.

Интегралы влажности/конденсата относятся только к заданным уровням профиля. Пространственная численная модель не подключена. Условия отрицательной температуры и жидкой воды не определяют интенсивность обледенения.

Динамика использует NCC с обратной проверкой до 1 пикселя, но не имеет устойчивого многокадрового сопровождения, независимой оценки высоты и облачной маски. Кандидат вращения не является обнаруженным или прогнозируемым ПМЦ.

Маршрут сопоставляется со сроком спутникового наблюдения и отдельно с профилем к моменту прохождения. Экстраполяции будущей погоды по одному снимку нет.

Данные и интерфейс

Импорт локальных каналов распознаёт соглашение A1/A2_YYYYMMDDhhmmss_chNN.tif. Произвольные TIFF, CADU/УФД и другие аппараты не декодируются. Орбита, время сканирования каждого пикселя и IFOV не загружены.

Карта строится на заданную область до 2048 px по стороне. Панорамирование не загружает новые тайлы. Анализ точки и маршрута обращается к исходным пикселям, а не к растянутому PNG. Natural Earth служит только грубой береговой подложкой, не навигационной или ледовой картой.

Эксплуатация

Один пользователь localhost, один фоновый расчёт и отдельная очередь скачивания. Нет общей авторизации пользователей, дисковых квот, автоматической очистки архива и полноценного версионирования внешних файлов.

Токены исчезают после остановки сервера; очередь сохраняется на паузе. Локальная SHA-256 подтверждает целостность, но не калибровку и не сумму поставщика. Экспорт с подписанными URL и внутренними путями не предназначен для открытой публикации.

Живой доступ GPTL и достоверность метеорологических диагностик проверяются отдельно от CI. Матрица CI подтверждает только те системы и сценарии, которые действительно выполнились для указанного коммита.

Научные выводы аудита

Рецепты RGB — реализация опубликованных диапазонов, а не доказательство физической эквивалентности каналов разных приборов. «Синий = лёд» не является универсальным правилом: в круглосуточной микрофизике синий вклад также зависит от температуры поверхности [1].

Кандидаты ледяного и водяного спектрального сигнала не сопровождаются подтверждённой облачной маской. Пороги 0.2.2 не обучались на региональной выборке и не имеют вероятностной интерпретации. Ночная ветвь применяется при расчётной высоте Солнца не выше −6°; это инженерное исключение сумерек, не порог поставщика.

Сопоставление Tя=T(z) оставлено как отдельный приближённый расчёт после подтверждения облака/непрозрачности. Температурная чувствительность — не доверительный интервал; радиометрия, эмиссия, параллакс и репрезентативность профиля в него не включены.

Отрицательная температура и жидкий конденсат описывают профильные условия, но не устанавливают интенсивность обледенения. Размер капель, скорость, тип воздушного судна и длительность воздействия не заданы [2].

Влагосодержание интегрируется из отдельного профиля, не выводится из яркости водяного канала. Вращение рисунка не заменяет атмосферную вихревость или набор условий развития полярной депрессии [3].

Внести поставку в GitHub

Репозиторий назначения: https://github.com/f2re/arktika-worker . Поставка не утверждает, что удалённый commit/PR уже создан. Скрипт использует обычную аутентификацию Git на компьютере владельца — токены в чат или файлы проекта передавать не нужно.

Из распакованной папки проекта:

python scripts/publish.py --checkout ../arktika-worker-git --push

На Windows с launcher:

py -3 scripts\publish.py --checkout ..\arktika-worker-git --push

Нужны установленный Git, настроенные user.name/user.email и доступ к репозиторию через HTTPS credential manager или SSH. Скрипт клонирует репозиторий в отдельную папку, проверяет чистоту рабочего дерева и manifest поставки, создаёт feature/meteo-workstation-v0.2.2 от origin/main, делает коммит и отправляет новую ветку. Main не перезаписывается; force push нет. После успеха печатается адрес сравнения веток для открытия pull request.

Если в main уже появились файлы реализации или рабочая папка содержит изменения, автоматическое наложение останавливается. Не обходить эту проверку удалением чужих изменений: сначала сравнить поставку с текущим репозиторием.

Без --push создаётся только локальный коммит. Проверку GitHub Actions и слияние PR выполнять после публикации. При ошибке аутентификации настроить Git стандартным способом; права чтения подключённого чата не означают наличия локального credential helper.

Manifest включает код, документацию, тесты и общедоступную подложку. Не включает спутниковые TIFF, runtime-базу, приватные URL/токены и изображения реальных сцен из приёмки. README использует обзор интерфейса без спутникового растра.
