# Подключение адаптера реанализа

Адаптер — установленный Python-код, который описывает источник, строит точный план, получает исходные наборы и нормализует их в общий контракт поля. UI не загружает Python-модули и не принимает пути к коду. Установка стороннего адаптера означает доверие к его коду; источник должен быть установлен в Python-окружения приложения и изолированного обработчика.

## Контракт

`AdapterImplementation` получает неизменяемый `AdapterMetadata`:

- `source_id`, `name`, `transport_id` и `auth_provider` — безопасный ID провайдера доступа; для источника без реквизитов указывается `none`;
- список `dataset_ids`, поддерживаемые ID полей, `adapter_version` и `maturity` (`implemented`, `experimental`, `planned`).

Для собственного провайдера объявите неизменяемую `credential_fields` схему из `CredentialField(id, label, input_type, required, help, max_length)`, `credential_format="fields"`, `credential_help` и список доменных имён `allowed_hosts`. Разрешены только поля `text` и `password`; ID и размеры проверяются при регистрации. Интерфейс строит форму из этой схемы через DOM API. Значения принимаются `POST /api/sources/credentials` как `{provider, format: "fields", values: {<id>: <строка>}}`, остаются в памяти процесса и передаются исполнителю отдельным аргументом `credential`. Их нельзя записывать в план, кэш, журнал, localStorage или экспорт. Очистка выполняется запросом `{provider, clear: true}`. Идентификатор провайдера должен быть одинаковым для адаптеров, совместно использующих реквизиты; схемы их полей должны совпадать. `allowed_hosts` — проверяемая декларация метаданных, она сама по себе не ограничивает сетевые вызовы доверенного установленного кода.

Реализация передаёт функции `planner(request)`, `fetcher(plan, credential, folder, progress)`, `normalizer(dataset, plan, area)` и `catalogue_builder()`. Удалённый `fetcher` возвращает список загруженных наборов и список provenance-записей; общий runtime вызывает `normalizer` на каждом наборе. Локальный импорт использует тот же нормализатор. Нормализатор обязан вернуть канонический xarray Dataset с двумерными `value`, `latitude`, `longitude`, CRS `EPSG:4326` и атрибутами `source`, `variable`, `unit`, `time`, `level`, `time_kind`, `resolution_km`, `area`. Поле, единицы, точный UTC-срок, уровень и геолокация сверяются с планом и каталогом до записи.

План включает `source`, `variable`, точный `time` в UTC, `level` (число или `null`), `area` в формате `[север, запад, юг, восток]`, `time_kind`, `resolution_km` и необязательные безопасные параметры провайдера. Секреты, URI, пути и реквизиты запрещены; реквизиты передаются отдельно в `fetcher` и не сохраняются. В provenance допускаются только безопасные идентификаторы, контрольные суммы, версии, переменные и область. Встроенные адаптеры заменять или удалять нельзя.

Каталог адаптера должен содержать `id`, `name`, `auth`, `start`, `step_hours`, `resolution_km` и список `variables`. У каждой переменной нужны `id`, `title`, `unit`, `vertical` (`pressure` или `surface`), список `levels` и поддерживаемые `styles`. Это описание становится источником названия и единиц в паспорте продукта.

## Установка

Python-пакет публикует entry point в группе `arktika.reanalysis_adapters`, например:

```toml
[project.entry-points."arktika.reanalysis_adapters"]
my_archive = "my_package.arktika_adapter:build_adapter"
```

Функция `build_adapter()` возвращает `AdapterImplementation`. Один и тот же установленный пакет должен быть доступен приложению и Python-окружению обработчика, которое настраивается штатным менеджером зависимостей проекта. Обработчик самостоятельно загружает только установленные entry points этой фиксированной группы; payload запроса не может указать модуль для импорта.

Для проверки адаптера нужны синтетический end-to-end тест через `scripts/reanalysis_worker.py`, тест отказа при несовпадении поля/срока/единиц/уровня/сетки и тест отсутствия секретов/URI в metadata и экспорте. Одобрение технических контрактов не является метеорологической валидацией продукта.
