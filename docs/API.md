# HTTP API 0.3.0

Это локальный API геоинформационной рабочей станции «Арктика-М», а не открытый веб-сервис в сети.
Для программного взаимодействия сначала выполните `POST /api/bootstrap` с `{"key":"ключ запуска"}`, полученным из вывода терминала при запуске сервера, и сохраните сессионную cookie `arktika_session`.
Во всех `POST`-запросах обязательны:
- `Content-Type: application/json`
- `X-Arktika-Request: 1`
- Допустимые заголовки `Host` (127.0.0.1) и `Origin`
- Лимит размера тела запроса — 4 МиБ

Без сессионной cookie доступны только статический интерфейс и `/health`. Секреты и токены хранятся исключительно в оперативной памяти процесса сервера и никогда не возвращаются в ответах API.

## 6. Кандидаты ПМЦ, подготовка архива и закладки

Все маршруты используют общую локальную сессионную защиту. Результаты детектора имеют статус `experimental` / `candidate`; наблюдательная маска и оценка оператора не меняют этот статус автоматически.

| Метод и путь | Входные параметры | Результат |
|---|---|---|
| `POST /api/pmc/run` | `{field_id, target_grid, observation_id?, thresholds?}` | Один расчёт по проверенному локальному полю мгновенного ветра 850 гПа. Поля и численные массивы из браузера не принимаются. Скачивание не запускается |
| `POST /api/pmc/archive/plan` | `{sources, start, end, area}` | План по точным срокам UTC, доступности ветра в кэше и перечню полей среды; без скачивания |
| `POST /api/pmc/archive/grid` | `{preset, width, area}` | Согласованная целевая сетка `target_grid` для района анализа |
| `POST /api/pmc/archive/prepare` | `{plan, target_grid, include_context?}` | Получение и нормализация входов; результат детектора ещё не рассчитывается |
| `GET /api/pmc/archive/prepare/state` | — | Состояние подготовки, `prepared`, `total`, `field_ids` только ветра 850 гПа, отдельные `context_field_ids`, `context_status` |
| `POST /api/pmc/archive/prepare/resume` | `{id}` | Продолжение подготовки с сохранёнными настройками и уже готовыми полями |
| `POST /api/pmc/archive/run` | `{plan, field_ids, target_grid, thresholds?}` | Фоновый расчёт выбранных сроков; до 128 полей ветра |
| `GET /api/pmc/archive/state` | — | Состояние и возможность продолжить архивный расчёт |
| `POST /api/pmc/archive/resume` | `{id}` | Продолжение с исходными сохранёнными порогами. Новые пороги требуют нового запуска |
| `POST /api/pmc/archive/cancel` | `{id}` | Остановка подготовки или расчёта; уже сохранённые данные остаются доступны |
| `GET /api/pmc/archive/report?id=…` | Идентификатор задачи | Отчёт по обработанным срокам, доступности и кандидатам |
| `GET /api/pmc/bookmarks` | — | `{bookmarks, limit}`: список без тяжёлых снимков состояния |
| `GET /api/pmc/bookmark?id=…` | Идентификатор закладки | `{bookmark}` со `state`, `availability`, статусом `saved_analysis_not_recomputed` и ограничением аттестации снимка |
| `POST /api/pmc/bookmarks/save` | `{id?, title, notes?, state}` | Создание либо обновление; возвращает `{bookmark}`. Неверное обновление не заменяет прежнюю запись |
| `POST /api/pmc/bookmarks/delete` | `{id}` | `{deleted, id}` |

`plan` содержит `sources`, `start`, `end`, `area: [N,W,S,E]`. `include_context` по умолчанию `false` для совместимости API; интерфейс предлагает `true`. Тогда готовятся 7 полей на срок ERA5/CARRA2 или 4 на срок MERRA-2. Недоступные у адаптера SST, лёд и доля суши MERRA-2 перечисляются в плане и не заменяются другим источником. Полный пакет ограничен 896 полями. Подробная матрица — [PMC_AUDIT.md](PMC_AUDIT.md).

В `thresholds` допустимы `minimum_vorticity_s-1` и `peak_vorticity_s-1` в с⁻¹, а не в отображаемых интерфейсом единицах `10⁻⁴ с⁻¹`. Применённые значения возвращаются в `parameters` ответа одиночного расчёта и в `frames[].result.parameters` архивного отчёта. Геометрия находится в `candidates[].geometry`: `coordinate_system=pixel_edges_rc`, `fill_rule=evenodd`, массив колец `rings`. Пары `[row, col]` задают **границы пикселей**, поэтому смещение `+0.5` к ним не добавляется. При `status=omitted_complexity_limit` массив `rings` пуст, и интерфейс показывает только пик кандидата; полный контур имеет `status=complete`.

### Состояние закладки

`state.schema_version` — `arktika.pmc_workspace.v1`. Сохраняются:

- `map`: `preset`, `width`, `height`, `crs`, `bounds: [left,bottom,right,top]`, `view: [x,y,width,height]`;
- `product_id`, `field_stack: [{id,style,opacity,visible}]`, `raster_visible`, `night_visible`;
- `result`: снимок результата либо `null`; `run`: выбранные `field_id`, `preset`, `width`, `observation_id`, `thresholds` либо `null`;
- `archive`: `sources`, `start`, `end`, `area`, необязательное `include_context` либо `null`;
- `annotations`: до 250 записей с `id`, `x`, `y`, `lon`, `lat`, `label`, `note`, `status`, необязательными `candidate_id`, `valid_time`, `source`.

Статусы пометок: `manual_candidate`, `expert_supported`, `rejected`. Для двух экспертных оценок обязательно основание. Координаты пиксельных точек и географические координаты должны согласовываться с сохранённой проекцией. Снимок результата сохраняет `maturity=experimental` и исходные статусы кандидатов.

Лимиты: 200 закладок, 2 МиБ JSON состояния на закладку, 8 полей в стеке, заголовок 160 символов, общие заметки 10 000, подпись пометки 120, основание 2000. Формат декларативный; нечисловые бесконечности, неизвестные поля верхнего уровня, реквизиты доступа и служебные ключи отклоняются.

`availability.missing_fields`, `changed_fields` и `product_available` отражают текущий кэш. Сохранённый результат не пересчитывается при чтении. SHA-256 состояния проверяет сохранённый JSON, но не доказывает происхождение клиентского снимка от серверного вычислителя; это прямо отражено в `snapshot_attestation`. Для воспроизводимого пересчёта нужны неизменные исходные файлы, паспорт и параметры.

PNG собирается браузером из согласованного снимка видимой карты, доступных изображений слоёв и метаданных. Отдельного серверного маршрута экспорта наноски нет.
