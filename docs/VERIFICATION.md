# Проверка и верификация

## Что означает успешный прогон

Технические проверки подтверждают только проверенные программные контракты на заданных входах. Они не измеряют метеорологическую точность, не удостоверяют доступ учётной записи к CDS/NASA и не заменяют валидацию по независимой выборке. Актуальный состав и результат проверок следует читать в журнале GitHub Actions **конкретного коммита**; прежнее число тестов не является постоянной характеристикой версии.

В локальном прогоне аудита 9 ноября 2026 года на Linux / Python 3.12.14 прошли **794 теста** за 69,5 с, базовая `check.py`, компиляция Python, проверка синтаксиса всех `static/*.js`, пять сценариев состояния и численный NetCDF smoke. Локальный Chromium недоступен из-за ограничений среды; эта запись не является подтверждением браузерного прогона. Браузер, Windows и macOS проверяются отдельно в CI.

## Воспроизводимые локальные команды

В окружении должны быть установлены зависимости из `requirements.txt` и `requirements-era5.txt`; для локального GRIB дополнительно `requirements-grib.txt`.

```bash
python check.py
python -m unittest discover -s tests -v
python -m compileall -q arktika server.py
python scripts/manifest.py --check
node --check static/app.js
node --check static/reanalysis.js
node --check static/pmc_workspace.js
node scripts/pmc_workspace_state_check.js
python scripts/pmc_workspace_browser_smoke.py --fixture-only --output browser-results/pmc-fixture
```

Последняя команда проверяет реальный численный путь без браузера: создаёт исходный синтетический NetCDF, импортирует и нормализует его штатным процессом, вычисляет завихрённость и выделяет кандидат с контуром. Она **не проверяет отрисовку или скачивание PNG**.

## Браузерная проверка

После установки Playwright и Chromium:

```bash
python -m playwright install chromium
python scripts/browser_smoke.py --output browser-results
python scripts/catalog_browser_smoke.py --output browser-results/catalog
python scripts/archive_browser_smoke.py --output browser-results/archive
python scripts/product_browser_smoke.py --output browser-results/products
python scripts/era5_browser_smoke.py --output browser-results/era5
python scripts/reanalysis_browser_smoke.py --output browser-results/reanalysis
python scripts/pmc_archive_browser_smoke.py --output browser-results/pmc-archive
python scripts/pmc_workspace_browser_smoke.py --output browser-results/pmc-workspace
```

Эти команды включены в `.github/workflows/tests.yml`. Артефакт `browser-results` содержит отчёты и снимки экрана; срок хранения ограничен настройкой workflow. Наличие скрипта само по себе не означает, что он выполнен.

Новый сценарий рабочего места ПМЦ проходит настоящий локальный HTTP API и численное ядро без подмены расчёта. Проверяются пустое состояние, сохранение календаря, согласованность проекции, реальные контуры, наложение полей, ручная пометка и её текст, PNG с растровыми слоями, сохранение закладки, перезагрузка и открытие без нового `/api/pmc/run`. Дополнительно проверяются узкий экран 390 пикселей, недоступный слой при экспорте, поздний ответ сохранения и откат неудачного восстановления. Синтетический пример отмечен как синтетический и не выдаётся за наблюдавшийся ПМЦ.

`pmc_workspace_state_check.js` отдельно проверяет пять сценариев гонок и отката на текущем production JavaScript. Это проверка состояния, а не замена настоящего браузера.

## Научные входы и численный метод

Тесты ПМЦ охватывают сферический метрический член и знак завихрённости, географическое направление ветра, единицы CF, регулярные и криволинейные сетки, согласованность affine transform, полярные ограничения, маски и NaN, равномерное сглаживание, геометрию областей, параметры детектора и совместимость паспортов.

Для нормализатора проверяются опубликованные обозначения CARRA2/MERRA-2, недопустимые переменные/уровни, сохранение пропусков и допустимые диапазоны долей. Для кэша и архивного расчёта проверяются файл, checksum, район, источник, срок, уровень и невозможность подменить ветер полями контекста. Для закладок проверяются перезапуск, повреждение JSON, отсутствие исходников, соответствие координат, HTTP-авторизация и CSRF-защита.

Публичные схемы CDS проверены для полного пакета ERA5 и CARRA2. Это подтверждает допустимость параметров запроса по проверенной схеме, но не доступ аккаунта, актуальность доступного архива или успешное скачивание. Нужен отдельный прогон с реквизитами пользователя и принятыми условиями каждой коллекции.

## Чего этот аудит не устанавливает

В аудите от 9 ноября 2026 года не выполнялись загрузка с секретами пользователя, оценка точности на реальных размеченных ПМЦ или новая радиометрическая калибровка МСУ-ГС. Ранее написанное об офлайн-приёмке спутниковых сцен не заменяет воспроизводимого протокола с идентификаторами входов, эталонами, методами и результатами; такой протокол этим изменением не предоставляется.

Для оперативного применения нужны независимые положительные и отрицательные случаи, разделение по событиям/сезонам/регионам, учёт наблюдательного покрытия, метрики ложных тревог и пропусков, ошибки координат и времени, чувствительность к настройкам каждого реанализа. Программные тесты не устанавливают эти показатели. Подробные выводы, ограничения и первичные источники — в [PMC_AUDIT.md](PMC_AUDIT.md).
