# Проверка и верификация

## Что означает успешный прогон

Технические проверки подтверждают только проверенные программные контракты на заданных входах. Они не измеряют метеорологическую точность, не удостоверяют доступ учётной записи к CDS/NASA и не заменяют валидацию по независимой выборке. Актуальный состав и результат проверок следует читать в журнале GitHub Actions **конкретного коммита**; прежнее число тестов не является постоянной характеристикой версии.

CI проверяет полный набор Python-тестов на Linux, Windows и macOS с Python 3.11 и 3.12, штатную установку ERA5 на трёх ОС, компиляцию Python, синтаксис JavaScript, шесть сценариев состояния, браузер и сборку пакета. Сквозная приёмка ПМЦ использует **реальные поля ERA5**; исходные URL, время и SHA-256 записываются в паспорт. Число тестов и результаты берутся из журнала конкретного коммита. Локальный численный прогон на реальном ERA5 импортировал все семь полей и выделил девять неподтверждённых кандидатов с полными контурами; он сам по себе не подтверждает браузерную проверку.

## Воспроизводимые локальные команды

В окружении должны быть установлены зависимости из `requirements.txt` и `requirements-era5.txt`; для локального GRIB дополнительно `requirements-grib.txt`.

```bash
python check.py
python -m unittest discover -s tests -v
python -m compileall -q arktika server.py
python scripts/manifest.py --check
node --check static/app.js
node --check static/reanalysis.js
node --check static/pmc_workspace.js
node scripts/pmc_workspace_state_check.js
python -m pip install numcodecs==0.17.1
python scripts/fetch_pmc_real_case.py --output /absolute/path/pmc-era5-real
```

Последняя команда получает реальный ERA5 за 2020-01-01 00:00 UTC из открытого ARCO ERA5 с проверкой закреплённых SHA-256. Полная команда импорта семи полей и расчёта приведена в [PMC_REAL_CASE.md](PMC_REAL_CASE.md): ключ `--numerical-only` выполняет её без браузера. Отсутствующий входной файл или паспорт приводят к отказу; генератора полей в сквозном сценарии нет.

## Браузерная проверка

После установки Playwright и Chromium:

```bash
python -m playwright install chromium
python scripts/browser_smoke.py --real-profile /absolute/path/pmc-era5-real/profile.json --output browser-results
python scripts/catalog_browser_smoke.py --output browser-results/catalog
python scripts/archive_browser_smoke.py --output browser-results/archive
python scripts/product_browser_smoke.py --output browser-results/products
python scripts/era5_browser_smoke.py --output browser-results/era5
python scripts/reanalysis_browser_smoke.py --output browser-results/reanalysis
python scripts/pmc_archive_browser_smoke.py --output browser-results/pmc-archive
# Затем полная команда PMC_REAL_CASE.md без --numerical-only.
```

Эти команды включены в `.github/workflows/tests.yml`. Артефакт `browser-results` содержит отчёты и снимки экрана; срок хранения ограничен настройкой workflow. Наличие скрипта само по себе не означает, что он выполнен.

Новый сценарий рабочего места ПМЦ проходит настоящий локальный HTTP API и численное ядро без подмены расчёта. Проверяются пустое состояние, сохранение календаря, согласованность проекции, реальные контуры, наложение полей, ручная пометка и её текст, PNG с растровыми слоями, сохранение закладки, перезагрузка и открытие без нового `/api/pmc/run`. Дополнительно проверяются узкий экран 390 пикселей, недоступный слой при экспорте, поздний ответ сохранения и откат неудачного восстановления. Входы рабочего места — реальный ERA5 с паспортом происхождения. Подтверждённый случай ПМЦ из одного такого прогона не выводится. Отдельно проверяется, что явно искусственный профиль отклоняется, а реальный профиль 2020 года не становится применимым к сцене 2026 года.

`pmc_workspace_state_check.js` отдельно проверяет шесть сценариев гонок, отката и порядка слоёв на текущем production JavaScript. Браузерный сценарий дополнительно проверяет читаемость кнопок, отсутствие пустой ошибки, положение изобар над заливкой и соответствие легенды способу отображения. Проверки состояния не заменяют настоящего браузера.

## Научные входы и численный метод

Тесты ПМЦ охватывают сферический метрический член и знак завихрённости, географическое направление ветра, единицы CF, регулярные и криволинейные сетки, согласованность affine transform, полярные ограничения, маски и NaN, равномерное сглаживание, геометрию областей, параметры детектора и совместимость паспортов.

Для нормализатора проверяются опубликованные обозначения CARRA2/MERRA-2, недопустимые переменные/уровни, сохранение пропусков, допустимые диапазоны долей и отказ для явно искусственного происхождения. Для профиля проверяются точный фактический срок CF, отказ для старого демонстрационного режима и сохранённых искусственных профилей. Математические unit-тесты используют аналитические массивы только для проверки формул и отказов; эти массивы не являются рабочими данными или итоговым примером анализа. Для кэша и архивного расчёта проверяются файл, checksum, район, источник, срок, уровень и невозможность подменить ветер полями контекста. Для закладок проверяются перезапуск, повреждение JSON, отсутствие исходников, соответствие координат, HTTP-авторизация и CSRF-защита.

Публичные схемы CDS проверены для полного пакета ERA5 и CARRA2. Это подтверждает допустимость параметров запроса по проверенной схеме, но не доступ аккаунта, актуальность доступного архива или успешное скачивание. Нужен отдельный прогон с реквизитами пользователя и принятыми условиями каждой коллекции.

## Чего этот аудит не устанавливает

В аудите от 9 ноября 2026 года не выполнялись загрузка с секретами пользователя, оценка точности на реальных размеченных ПМЦ или новая радиометрическая калибровка МСУ-ГС. Ранее написанное об офлайн-приёмке спутниковых сцен не заменяет воспроизводимого протокола с идентификаторами входов, эталонами, методами и результатами; такой протокол этим изменением не предоставляется.

Для оперативного применения нужны независимые положительные и отрицательные случаи, разделение по событиям/сезонам/регионам, учёт наблюдательного покрытия, метрики ложных тревог и пропусков, ошибки координат и времени, чувствительность к настройкам каждого реанализа. Программные тесты не устанавливают эти показатели. Подробные выводы, ограничения и первичные источники — в [PMC_AUDIT.md](PMC_AUDIT.md).
