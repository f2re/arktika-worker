## 2. Проверка веб-интерфейса в браузере

Браузерные тесты выполняются скриптом `scripts/browser_smoke.py` через Chrome DevTools Protocol / Playwright:
- **Разрешения экрана**: Тестируются стандартное рабочее место 1536×960, компактный экран 1024×768 и мобильный экран 390×844.
- **Интерактивные сценарии**:
  - Открытие Центра справки (`#helpDialog`), переключение всех 5 тематических вкладок, проверка отображения диаграмм и инструкций по токенам.
  - Открытие диалога «Источники данных», проверка ссылок и полей ввода токенов CDS и Earthdata.
  - Навигация по календарю, смена космических аппаратов и выбор сеансов съёмки.
  - Взаимодействие с картой: зумирование, панорамирование, переключение пресетов и ночной маски.
  - Инспектор точки: щелчок по растру, расчёт спектральных разностей, проверка фазовых гипотез.
  - Построение маршрута: добавление путевых точек кликами по холсту, смена скорости, экспорт CSV.
  - Управление слоями реанализа: добавление слоев, регулировка прозрачности, смена режимов отображения (заливка, изолинии, векторы).
- **Критерий успешности**: Полное отсутствие ошибок в консоли JavaScript (`console.error`), предупреждений CSP (`Content-Security-Policy`) и сбоев отрисовки DOM.

## 3. Проверка на реальных спутниковых снимках

Для подтверждения физической корректности алгоритмов проведена автономная офлайн-приёмка на контрольных сеансах съёмки «Арктика-М» №1 и №2:
- **Проверка геопривязки**: Совпадение контуров побережий островов Северного Ледовитого океана (Новая Земля, Шпицберген, Северная Земля) с береговой векторной подложкой.
- **Радиометрическая согласованность**: Проверка динамического диапазона температурных каналов 4–10 над ледовым покровом, морской поверхностью и глубокой конвекцией.
- **Орбитальная геометрия**: Сопоставление расчётного зенитного угла КА по SGP4 с фактическим положением спутника на орбите «Молния» в моменты апогея над арктическим регионом.

*Примечание: Исходные GeoTIFF снимков и их производные растры являются собственностью оператора космической системы и не включаются в публичный репозиторий.*

## 4. Разграничение технической и метеорологической верификации

В соответствии с правилами проекта (`AGENTS.md`) строго разделяются два уровня подтверждения готовности:

1. **Техническая верификация (ПОДТВЕРЖДЕНО)**:
   - Корректность программного кода, типов данных, сетевых протоколов и математических формул.
   - Защита памяти от утечек секретов и токенов.
   - Воспроизводимость результатов расчёта при неизменных входных данных.
   - Соответствие форматов файлов международным стандартам (OGC GeoTIFF, CF-1.8 NetCDF4, GeoJSON).

2. **Метеорологическая валидация (ТРЕБУЕТ НЕЗАВИСИМЫХ ИЗМЕРЕНИЙ)**:
   - Радиометрическая точность калибровки МСУ-ГС без официального подтверждения поставщика остаётся **исследовательским допущением**.
   - Восстановленная высота ВГО по профилю $T(z)$ не учитывает полупрозрачность перистых облаков и требует валидации по спутниковым лидарам (CALIOP) или наземным радарам.
   - Спектральные фазовые признаки и кинематические кандидаты вихрей не являются официальными штормовыми предупреждениями и требуют подтверждения дежурным синоптиком.
