# Импорт спутниковой маски для экспериментального сравнения

Диалог «Экспериментальные кандидаты ПМЦ» принимает три файла: одноканальный `labels.tif`, одноканальный `coverage.tif` и `metadata.json`. Два GeoTIFF должны точно совпадать друг с другом по метрической проецированной сетке; эта исходная сетка может отличаться от сетки расчёта. При архивном сравнении обе маски отдельно перепроецируются на целевую сетку методом nearest-neighbor. Повёрнутый affine источника допускается; целевая сетка остаётся регулярной и неповёрнутой.

В растрах разрешены только целочисленные значения `0` и `1`; `nodata` в GeoTIFF не задаётся. В `labels.tif` единица означает вручную или внешним алгоритмом размеченного кандидата, ноль — наблюдённое отсутствие класса внутри покрытия. `coverage.tif` отдельно задаёт, где наблюдение действительно существует. Положительная метка вне покрытия отклоняется. Неизвестное покрытие не становится отрицательной меткой.

Пример sidecar:

```json
{
  "schema_version": "arktika.pmc_satellite_observation.v1",
  "observation_ref": "scene-20240101-a",
  "source": "satellite-provider",
  "product": "reviewed-pmc-labels",
  "product_version": "1",
  "valid_time": "2024-01-01T00:00:00Z",
  "label_convention": "0=no_pmc,1=pmc_candidate",
  "qc_status": "not_assessed",
  "grid": {
    "crs": "EPSG:3413",
    "width": 768,
    "height": 768,
    "transform": [1000, 0, -384000, 0, -1000, 384000],
    "resolution_x_m": 1000,
    "resolution_y_m": 1000
  },
  "nodata": null
}
```

Замените значения примера реальными сведениями о наблюдении и точными параметрами GeoTIFF. Срок должен соответствовать сроку анализа в UTC. Sidecar не принимает URI, приватные пути, произвольные поля и секреты. Значение `qc_status` может быть только `not_assessed` или `user_reviewed`; оно фиксирует статус разметки, но не подтверждает её правильность.

Импорт ограничен общим HTTP-пакетом 16 МиБ; хранилище сохраняет только сжатые двоичные маски и контрольную сумму. Маска получает статус `imported_unverified`. Сравнение возможно лишь при единственном наблюдении с точным сроком UTC; перепроецирование — техническое выравнивание сетки и не подтверждает корректность спутниковой классификации. Вне исходного покрытия остаётся `unknown`. Если несколько наблюдений совпали по времени или геосетка не прошла проверку, отчёт сохраняет неизвестный статус и безопасный код причины. Отчётные IoU/POD/FAR — только пиксельные показатели совпадения масок, а не метеорологическая оценка, детекция или подтверждение ПМЦ. Этот путь не ищет точку зарождения.

Перед сохранением тот же пакет можно отправить в `POST /api/pmc/observations/preview`. Это проверяет файловый формат, sidecar, CRS, геометрию, бинарные метки и допустимость положительных меток только внутри покрытия, затем возвращает сетку, число покрытых/неизвестных ячеек, количество положительных меток внутри покрытия и SHA-256 пакета (содержимое обоих GeoTIFF и точные байты `metadata.json`). Предпросмотр не создаёт локальную запись и имеет `status=preview_only`, `ingestion_status=not_ingested`. Статистика покрытия и нулевые метки не являются метеорологическим QC или отрицательной выборкой ПМЦ. При сохранении сервер повторяет валидацию; UI сверяет хеш повторного предпросмотра с подтверждаемым пакетом.

Архив также выдаёт `candidate_emergence_evidence` для первой фиксации каждого сегмента трека. Запись связывает срок и ID первого кандидата с предыдущим ожидаемым модельным кадром: обработанный кадр без кандидатов, кадр с другими кандидатами, ошибка, пропуск, конфликтующие записи или левое цензурирование на начале окна различаются явно. Добавлены ссылки на межмодельные совпадения и спутниковое pixel-сравнение только для точного срока первого появления; без пары сохраняется неизвестность. Это журнал происхождения кандидатного результата, а не детекция физического зарождения: пустой модельный экран и отсутствие спутникового сравнения не означают отсутствия ПМЦ.
