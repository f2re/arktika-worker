# Арктика-М 0.9.3 — дискретное разделение пиков в кандидатных областях

Компоненты с несколькими изолированными максимумами теперь делятся на отдельные кандидатные области по дискретным суперконтурным ядрам выше saddle-уровней. Незанятые контуром пиксели назначаются ближайшему seed в проецированной целевой сетке. Область с одним изолированным пиком остаётся единым объектом; отсутствие изоляции, неполные границы или лимит вычислений сохраняют цельную область с явным статусом. Разделённые объекты остаются `candidate / not_confirmed`. Это дискретная аппроксимация: она не воспроизводит интерполяцию контуров/valley-line, полный QC и спутниковую морфологию IMPMCT. Метеорологическая пригодность, реальные спутниковые разметки и точность не проверялись. Полное сопровождение со steering/split/merge и определение genesis не реализованы.

# История релиза 0.3.0 — поля реанализа и многослойная карта

## Исправления относительно PR №11

Независимые реквизиты CDS сохраняются в памяти при переключении экспериментальной ERA5-калибровки на GDEX. Минимальные версии библиотек и исправления независимого выбора области из main сохранены. Версия приложения, API и манифеста согласована.

## Установка и обновление

Распакуйте `arktika-worker-v0.3.0.zip` в отдельную папку. Linux/macOS: `sh install.sh`, затем `sh start.sh`. Windows: `install.cmd`, затем `start.cmd`. Нужен Python 3.10+; матрица CI использует 3.11/3.12. Архив содержит исходники и установочные скрипты, а не автономную поставку Python и зависимостей. Кэш полей раннего PR №11 физически сохраняется, но автоматически не переиспользуется: изменились формат метаданных и временная семантика MERRA-2. Получите эти поля повторно либо сохраните старые экспорты отдельно. Новый кэш и новый стек восстанавливаются после перезапуска.
