# Арктика-М 0.4.2 — интерактивный экспериментальный расчёт кандидатов ПМЦ

В экран «Архив ПМЦ» добавлен сценарий расчёта из одного уже кэшированного ветрового поля ERA5 или MERRA-2 на 850 гПа. Он вычисляет относительную вихревость, перепроецирует её в одну из поддержанных метрических сеток, запускает экспериментальный пороговый детектор и показывает кандидатов таблицей и пиковыми точками на карте, когда совпадают область и проекция. Доступен JSON-отчёт с паспортом и ограничениями.

Расчёт не загружает архив, не продолжает несколько сроков, не поддерживает CARRA2 и не получает/размечает спутниковые наблюдения. Спутниковое сравнение отображается только при наличии атрибутированной маски; автоматического спутникового детектора нет. Gaussian-сглаживание прототипа отличается от baseline IMPMCT. Результат помечен `experimental / candidate_only / not_confirmed`: он не подтверждает ПМЦ, метеорологическую точность или место зарождения.

## Проверка

Локально прошли 572 технических unittest, Python `compileall`, синтаксис всех `static/*.js`, проверка манифеста и браузерные проверки пустого состояния/ошибки/календаря/адаптивной ширины. Тестовые данные синтетические. Реальный OAuth/CDS/Earthdata и метеорологическая валидация на независимом спутниковом архиве не проверялись.

План дальнейшей работы: [DEVELOPMENT_PLAN_2026-10.md](docs/DEVELOPMENT_PLAN_2026-10.md).

# Арктика-М 0.4.1 — безопасный трекер кандидатов ПМЦ

Исправительный исследовательский выпуск поверх 0.4.0.

## Новое

- Добавлено экспериментальное библиотечное связывание центроидов кандидатов ПМЦ между последовательными сроками на строго совпадающих источнике и сетке. Сроки должны быть точными UTC, расстояние оценивается в метрической проекции, неоднозначные связи обозначаются; трек остаётся `candidate_only / not_confirmed`. Модуль пока не подключён к загрузчику, интерфейсу или экспорту и не определяет место зарождения.
- Ужесточена проверка ориентации вектора ветра. Отсутствующий признак grid-relative больше не считается доказательством восточной/северной системы: нужны проверяемые CF `standard_name` либо явный GRIB-флаг. Для направления CARRA также требуется подтверждённый `wind_from_direction`.
- Увеличено время ожидания в двух синтетических тестах длительной фоновой ERA5-задачи; сами данные и вычисления тестов остались искусственными.

## Проверка и пределы

Локально прошли 535 unittest, Python `compileall`, `node --check` для `static/*.js`, `git diff --check` и проверка `MANIFEST.json`. GitHub Actions ещё должны пройти перед выпуском архива. Ветер проверен на синтетических контрактах, не на реальной загрузке. Вихревость из ветра, многослойный архивный запуск, спутниковая детекция/сопоставление и оценка genesis не реализованы. Это не воспроизведение IMPMCT, не operational product и не метеорологическая валидация.

План развития: [DEVELOPMENT_PLAN_2026-10.md](docs/DEVELOPMENT_PLAN_2026-10.md).

# Арктика-М 0.4.0 — паспорта продуктов, шкалы и возобновление запросов

## Новое

- Численные и архивные продукты получают паспорт происхождения: версия алгоритма, величина, единицы, вид данных, UTC, исходная и расчётная сетки, nodata и контроль качества.
- Для непрерывного продукта можно независимо сохранить пределы и палитру. Изменение перерисовывает отображение из `values.tif`; численные данные, алгоритм и паспорт остаются прежними. Готовые RGB-композиции и категориальные продукты не перекрашиваются.
- Реестр адаптеров описывает доступные поля ERA5, CARRA2 и MERRA-2. Запрос к источнику без нужных реквизитов сохраняется и продолжается с тем же ID после ввода доступа. После остановки сервера безопасный план можно возобновить; секреты и URI в план не записываются.
- Добавлено изолированное исследовательское ядро обнаружения кандидатов ПМЦ по вихревости 850 гПа. Любой выход помечен `candidate / not_confirmed`. Сравнение масок доступно лишь при совпадении времени и полной сетки.
- Добавлена форма «Архив ПМЦ» и `/api/pmc/archive/plan`: проверяют период, область, частоту источников и известные входы. Они строят только план: поля не загружаются, детектор не запускается и место зарождения не выдаётся.
- Производные продукты получили локальный контракт адаптеров и защищённый каталог `/api/derived-adapters`. Встроенный пример скорости ветра показывает схему регистрации; произвольный исполняемый код из API/UI не загружается.
- Если доступ к реанализу запрошен, его можно отменить прямо из диалога поля; запрос можно сохранить для продолжения с настройкой реквизитов.

## Ограничения проверки

Для 0.4.0 локально прошли 522 unittest и браузерные smoke-сценарии на синтетических данных; для проверки текущего выпуска см. раздел выше. Реальные учётные данные CDS/Earthdata, независимая точность калибровки и метеорологическая точность не проверялись. Архивный интерфейс ПМЦ пока только строит план: получение ERA5/CARRA/MERRA по единой задаче, расчёт вихревости и спутниковое сопоставление не реализованы. Прототип использует Gaussian-сглаживание σ=60 км, а опубликованный IMPMCT — равномерный фильтр радиусом 60 км.

# История релиза 0.3.0 — поля реанализа и многослойная карта

Первый GitHub Release рабочего места с самостоятельным сценарием ERA5, CARRA2 и MERRA-2. Спутниковый просмотр и калибровка остаются отдельными задачами.

## Новое

«Источники данных → Добавить поле» и «Слои → ＋»: выбор источника, величины, уровня, точного срока UTC и области без обязательного спутникового снимка или RTTOV. Настройка CDS/Earthdata доступна из окна поля с возвратом к выбранным параметрам.

Загрузка через CDS, поиск объявленных файлов MERRA-2 через NASA CMR и выборка OPeNDAP; проверяемый локальный кэш и импорт NetCDF/GRIB. До восьми полей поверх спутника: заливка, изолинии, стрелки географического ветра, непрозрачность, порядок и видимость. Состав карты сохраняется.

Совместный инспектор исходных значений и разности A − B при совпадении величины, уровня, времени, единиц и временной семантики. Разность на более грубой исходной сетке с общей маской; перепроецирование не повышает разрешение. Экспорт CF-NetCDF и JSON с происхождением данных.

## Исправления относительно PR №11

Поверхностные поля MERRA-2 запрашиваются из мгновенной часовой коллекции M2I1NXASM, не из часовых средних. Анализы CARRA2 не заменяются промежуточными прогнозами; текущие параметры и опубликованные годы сверяются со схемой CDS. Усилены проверки единиц, времени, уровней, пропусков, версий файлов и перенаправлений HTTPS.

Независимые реквизиты CDS сохраняются в памяти при переключении экспериментальной ERA5-калибровки на GDEX. Минимальные версии библиотек и исправления независимого выбора области из main сохранены. Версия приложения, API и манифеста согласована.

## Установка и обновление

Распакуйте `arktika-worker-v0.3.0.zip` в отдельную папку. Linux/macOS: `sh install.sh`, затем `sh start.sh`. Windows: `install.cmd`, затем `start.cmd`. Нужен Python 3.10+; матрица CI использует 3.11/3.12. Архив содержит исходники и установочные скрипты, а не автономную поставку Python и зависимостей. Для локального GRIB дополнительно установите `requirements-grib.txt` в окружение приложения.

Перед обновлением остановите сервер и сохраните резервную копию папки состояния. Спутниковые исходники не перемещаются. Укажите прежний `--data-dir` для продолжения работы с каталогом. Не запускайте две версии с одной базой.

Кэш полей раннего PR №11 физически сохраняется, но автоматически не переиспользуется: изменились формат метаданных и временная семантика MERRA-2. Получите эти поля повторно либо сохраните старые экспорты отдельно. Новый кэш и новый стек восстанавливаются после перезапуска. Секреты остаются только в памяти процесса и вводятся заново после остановки сервера.

## Проверка и ограничения

Публикация релиза разрешена только после успешного прохождения всей матрицы Python, установки расширенного окружения, браузерных сценариев, проверки коэффициентов и сборки архива. `build-info.json` содержит точный коммит и контрольные суммы; журнал CI доступен на вкладке Actions.

Тестовые поля синтетические и проверяют программные контракты. Живой вход и скачивание от имени пользователя CDS/Earthdata, а также независимая метеорологическая верификация не выполнялись. Доступность конкретных дат зависит от источника и принятых пользователем условий.

Детальная береговая линия, тайлы и автоматические пространственные профили вдоль маршрута не входят в этот релиз. CARRA2 не получает вымышленные компоненты ветра при отсутствии подтверждённого направления. Кандидат вращения спутникового рисунка не объявляется подтверждённым ПМЦ.
